Mastering AWS Systems Manager (SSM)

📌 Introduction

Managing a fleet of EC2 instances or on-prem servers can be overwhelming—patching, running commands, collecting logs, and ensuring compliance.

AWS Systems Manager (SSM) is like a remote control for your AWS and on-prem infrastructure. With SSM, you can:

  • Securely connect to EC2 instances without SSH keys
  • Automate patching and updates
  • Run scripts across multiple instances at once
  • Store and retrieve secrets/parameters
  • Monitor compliance and security

🔑 Key Features of AWS Systems Manager

  • Session Manager

    – Securely access your instances via AWS Console or CLI (no need for port 22 SSH).

  • Run Command

    – Execute scripts/commands across multiple EC2 instances in parallel.

  • Patch Manager

    – Automate OS and application patching.

  • Parameter Store

    – Securely store config values, API keys, and secrets.

  • Automation

    – Run pre-built or custom automation workflows (like restarting services).

🛠️ Setting Up AWS Systems Manager

1. Attach IAM Role to EC2 Instance

Create an IAM Role with the following policy:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ssm:*",
        "ec2messages:*",
        "cloudwatch:*",
        "logs:*"
      ],
      "Resource": "*"
    }
  ]
}

👉 Attach this role (e.g., AmazonSSMManagedInstanceCore) to your EC2 instance.


2. Install & Start the SSM Agent

# For Amazon Linux / RHEL
sudo yum install -y amazon-ssm-agent
sudo systemctl enable amazon-ssm-agent
sudo systemctl start amazon-ssm-agent

# For Ubuntu/Debian
sudo snap install amazon-ssm-agent --classic
sudo systemctl enable amazon-ssm-agent
sudo systemctl start amazon-ssm-agent


3. Verify SSM Agent Status

aws ssm describe-instance-information

If the instance is listed, it’s successfully registered! ✅

🚀 Using AWS Systems Manager

1. Connect to an Instance (Session Manager)

aws ssm start-session --target <Instance-ID>

Now you’re inside the instance without needing SSH keys or open ports 🎉


2. Run Commands Across Instances

aws ssm send-command \
  --targets "Key=instanceIds,Values=<Instance-ID>" \
  --document-name "AWS-RunShellScript" \
  --comment "Update packages" \
  --parameters 'commands=["sudo yum update -y"]'


3. Store Parameters & Secrets (Parameter Store)

aws ssm put-parameter \
  --name "DB_PASSWORD" \
  --value "SuperSecret123" \
  --type "SecureString"


4. Automate Patching

Enable Patch Manager to automatically install security updates and increase compliance.

🌍 Real-World Use Case

Imagine you have 50 EC2 instances running across different environments. Instead of manually SSH-ing into each one:

  • Use Run Command to apply updates in one go.
  • Use Session Manager for secure troubleshooting.
  • Store DB passwords in Parameter Store instead of hardcoding them.
  • Automate patching to meet compliance with minimal effort.

Automation and Hybrid Activation

Automation

Automates repetitive IT tasks like patching, AMI creation, or instance configuration. You can chain multiple steps using automation documents.

Hybrid Activation

Allows you to use SSM with on-premises servers or VMs. You generate activation codes in the AWS console, install the SSM agent, and register the servers.
